# 🟠 Share 4.0

**A from-scratch, community rebuild of the discontinued Share Weibo client.**

Share 3.9.5 shipped its last update in 2021 and its protocol stack has been
rotting since. This project replaces the app entirely — a modern
Kotlin + Compose client whose **native protocol layer is reverse-engineered
byte-for-byte from the original**, not guessed.

> [!IMPORTANT]
> **Protocol fidelity over reimplementation.** The Weibo mobile API is an
> adversarial surface: one wrong parameter and the server answers
> `-105 客户端身份校验失败`. Share 4.0 does not approximate the protocol —
> every signature algorithm was recovered from the original binaries and is
> pinned against golden values before it ships.

## The fidelity discipline

Third-party clients usually die by drift — a parameter "improved" here, a
header dropped there, until risk control notices. This project treats the
protocol as a spec to be *archaeology*, not a suggestion:

| Rule | Enforcement |
| --- | --- |
| Signatures are exact | `s` / `i` / `p` / `mfp` implementations are unit-tested against golden values generated by a Python reference decoder of the original `.so` files. A single changed nibble fails the build. |
| Requests look byte-identical | Parameter order, URL encoding, and headers mirror the original okhttp interceptor chain — including quirks the original shipped with (yes, even the ones that look like bugs). |
| The request signature is computed, never faked | The original `libwbutil.so` is embedded with its signature *gate* neutralized (2 instructions) while the algorithm itself runs untouched — the gate guarded entry, not math. |
| Every login detour is a real detour | The server's "please verify" page (`8599 → errurl`) is a WebView speaking the original JSBridge protocol (`loginWithALT`) — the same flow the original app used, reconstructed. |
| Degradation is explicit | If a native channel fails, the app says so and falls back to an embedded `m.weibo.cn` session — it never silently pretends an empty feed is a loaded one. *(That exact bug shipped in an early build; found the hard way.)* |

## The signing stack, briefly

The interesting part of rebuilding Weibo in 2026 is that the *server* still
speaks 2021. Four independent credentials ride on every authenticated
request — all recovered, all live-tested:

| Credential | What it is | Recovered from |
| --- | --- | --- |
| `s` | 8-char hash signature over the request identity | `libwbutil` + `libwbgjb` (cross-validated against a public Weico-intl reversing writeup) |
| `i` | 7-char device fingerprint | `libwbutil::getIValue`, instruction-by-instruction |
| `p` | RSA-sealed password (117-byte blocks) | `libSecShell::secP`, public key extracted from the constant table |
| `cum` | Per-request URL signature (SHA-256 × DES cascade) | embedded `libwbutil`, gate-patched |

## Build

JDK 17 · Android SDK 35 · that's it.

```bash
git clone https://github.com/Deyu008/share4 && cd share4
./gradlew assembleRelease   # → app/build/outputs/apk/release/ (~2.5 MB, R8 + resource shrink)
./gradlew :protocol:test    # golden-value suite for every signing algorithm
```

The protocol module is plain JVM — the test suite runs without a device,
which is exactly how the golden values were produced: Python decodes the
originals, Kotlin replays them, CI-able diff.

## Status

Verified on the live API: anonymous registration, the complete SMS login
chain (including the risk-control WebView round-trip), session persistence
and renewal, timeline rendering through the native `cardlist` channel.

In flight: on-device validation of the native signing bridge (the
x86-emulator arm-translation layer computes untrustworthy crypto — a
classic trap this project documented the hard way; ground truth requires
an arm64 handset), posting, multi-account.
